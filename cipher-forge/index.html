03 / protector

输入 JS，输出混淆 HTML

粘贴 JS，或整份 HTML 文档：前者生成保护页，后者保持结构不变、只替换内联 script 的内容。

ready

整页 HTML 模式下：标题、样式、结构、属性一律原样保留，只有内联 script 的正文被替换为加密切片，页面解析到该位置时同步解密执行；外链 script 与 type=module 保持不变。 JSFuck 模式只包裹引导器（bootstrap），且仅适用于 JS 输入；输出体积约为输入的 4–6 千倍。

04 / threat model

它提高成本，但它不是加密

真正的作用

抬高静态阅读、断点调试、LLM 批量还原与跨会话复用的成本。多态 handler 让每次刷新页面的字节含义都不同。

边界

只要代码在用户机器上执行，确定性 就无法隐藏。密钥、许可证判定、计费等敏感逻辑应放在服务端；前端混淆只保护“阅读门槛”。

诱饵层（BLA）

页面内确实存在假端点、假密钥、自洽但错误的 shadow 调用链。它们不参与真实路径，只消耗分析预算。
